Steam client (Linux, arm64) - packages for DroidDeck's local install
====================================================================

DroidDeck cannot ship Valve's Steam client - it is not redistributable - so a Steam session
downloads it from Valve's CDN the first time it runs. On a network where that CDN is slow or
unreachable, fetch the packages here and install them from DroidDeck's Steam settings
("Steam client" row -> "From folder").

Branch    : steamdeck_publicbeta   (what Deck mode uses; the same client as publicbeta's arm64)
Version   : 1791415817
Components: 17 files, 360,318,017 bytes (343.6 MiB) compressed, ~932 MB unpacked
Taken from: Valve's manifest on 2026-10-09. Valve replaces these files whenever it updates the
            client, so this list goes stale - `download-steam-client.bat --list` prints the
            current one, and the tool itself always follows the manifest rather than this list.
            Refreshed here when Valve replaced five of the seventeen between 10-07 and 10-09 -
            bins_hardware_all, bins_linuxarm64_linuxarm64, bins_sdk_linuxarm64_linuxarm64,
            sdl3_linuxarm64_linuxarm64 and steamui_websrc_all, 171.5 MB together. Re-running the
            downloader fetched exactly those five; the other twelve verified and were skipped.
            That replacement is also why a component's file name ends in its sha256: a new build
            arrives as a new name beside the old file rather than over it, so the folder can hold
            both and only the manifest decides which one the install uses. Copy the folder on the
            day you fetch it and the build numbers cannot drift apart like that. Both CDN edges
            agreed on the newer manifest, so this was a real update and not an edge-cache
            difference.

Downloading: run `download-steam-client.bat` at the project root. It fills
DroidDeckCOK\FirstLocalInstall\steam-client with the 17 packages plus the manifest, verifying each one
against the manifest's sha256, and resumes wherever it left off if it is run again. `--out DIR` puts
them elsewhere. Two git-ignored payload folders sit side by side: DroidDeckCOK\FirstLocalInstall is
the device bundle - the built APK is dropped in beside it, and it is the folder copied across - while
the checkout's own FirstLocalInstall is only a staging area. The downloader defaults to the bundle,
so a fetch lands where it is used.

Which CDN: Valve serves these files from two edges - client-update.akamai.steamstatic.com and
client-update.fastly.steamstatic.com - and neither has a point of presence in mainland China. The
bare client-update.steamstatic.com is a third name for the Fastly one, resolving to the same
address, so it is not a third option. Nor is there a Chinese mirror to prefer: Valve's China CDN
hosts (steamstatic.com.8686c.com, st.dl.eccdnx.com, dl.steam.clngaa.com) carry game content depots
only, never client-update. Which edge is quicker is therefore a property of the line, and it has
gone both ways between runs here: Akamai measured 4.6x the Fastly edge on a small component and
1.1x on a 4 MiB one from one line, while a 1 MiB sample from another came out 1.6x the other way.
So with no options the tool measures both - one MiB ranged read each, of the largest component -
and takes the faster, falling back to the other if a component still fails. `--official` pins the
Fastly edge, which is what the device's own install script uses; `--host HOST` (or the
DROIDDECK_STEAM_HOST environment variable) names one host or whole base URL and skips the
measuring - point it at a proxy of your own and the entire set comes through that.

None of this touches what the device itself does on first run. droiddeck-steam-install has
client-update.fastly.steamstatic.com written into it, with no mirror to fall back to and no choice
of edge, so getting a folder onto the device is the only way to keep that download off the line -
and the reason this file exists.

The rest of that folder, which the play page's "First-time local install" button installs in this
order: linuxfs.tar.zst (the runtime), the Proton <build>.tar.zst, steam-client\, desktop.tar.zst
(the LXQt desktop) and fonts\ (CJK fonts, copied into the rootfs's /usr/share/fonts/TTF and picked
up by fontconfig). The desktop's own entry - its download, its size and its sha256 - is in the
hosted catalog, so what is below is a snapshot of it, not the source:

From a network that cannot reach github.com, the same file comes through one of the app's
accelerators - `https://gh-proxy.com/<url above>` was the fastest of them on 2026-10-07.

The button that offers all of this belongs while the device is short of any of it. The runtime,
Valve's Proton and the client always count; the rest is read off the folder the last run came
from, which the app remembers - while that folder still holds something the device has not got
(the desktop, fonts, a third-party Proton) the button stays, and it goes once everything in it is
in. With no folder remembered - none picked yet, or the one picked taken off the device - the
desktop's own check stands in.

The folder is handed to the runtime's droiddeck-steam-install, which reads the manifest, uses
every component it finds in the folder and downloads only the rest. Each file - local copy or
download - is checked against the sha256 in the manifest, so a truncated or renamed file is
rejected rather than installed. Nothing needs to be renamed by hand: the file names below are
the names the manifest itself uses.

Using it
--------

1. Put all 17 files (and the manifest, if the device has no network at all) in one folder - any
   name, any location, but flat: the install reads that folder's own entries, not subfolders.
2. Copy the folder to the device, e.g. /storage/emulated/0/Download/steam-client.
3. DroidDeck -> Steam settings -> Steam client -> "From folder", and pick it.
4. The install needs about 2 GB free: the client unpacks to a little under 1 GB, and one
   component's zip sits beside it while it is being unpacked.

The row only appears while the client is missing. Repairing a client that is already installed
is the "Repair Steam client" button above it - but note that a repair re-downloads from Valve
rather than from the folder.
